# نظام تحليل ترحيل المتأخرات الشهري

Monthly Delinquency Migration Analysis System — the default application of this site:
<https://fadiramzy.github.io/test/>

تطبيق ويب عربي (RTL) يعمل بالكامل داخل المتصفح دون خادم؛ البيانات تُحفظ محليًا في IndexedDB.

## ما الذي يقدّمه

| القسم | المسار | الوظيفة |
| --- | --- | --- |
| لوحة المقارنة | `#/` | مقارنة أي شهرين: عدد العملاء والمبالغ لكل شريحة والفرق والنسبة، مع جدول مقارنة الفروع وتصدير Excel |
| إدخال البيانات الشهرية | `#/entry` | «إدخال يدوي» أو «رفع PDF»: عدد العملاء ومبلغ المتأخرات لكل شريحة ولكل فرع، وجدول الشهور المحفوظة (تعديل/حذف) |
| المقارنات المحفوظة | `#/saved` | نسخ مجمّدة من المقارنات للرجوع إليها |
| النسخ الاحتياطي | `#/data` | ثلاثة أزرار فقط: تصدير Excel، تنزيل نسخة احتياطية JSON، رفع نسخة احتياطية JSON |

شرائح التأخير الخمس: **1–30**، **31–60**، **61–90**، **91–120**، **أكثر من 120 يومًا (NPL)**.

### رفع PDF (تقرير «اعمار الديون»)

في تبويب الإدخال: «رفع PDF» ← اختيار الملف ← جدول مراجعة قابل للتعديل ← «تأكيد وحفظ» أو «تصدير Excel».
الملف يُقرأ داخل المتصفح (pdf.js) ولا يُرسل إلى أي خادم.

- **المصدر:** قسم «المحفظة في ظل المخاطر» فقط. يُحدَّد كل جدول من عنوان القسم المكتوب في رأسه
  (يتكرر الرأس في كل صفحة)، وقسم «المتأخرات» يُتجاهل تمامًا. إن لم يوجد القسم المطلوب يُرفض الملف.
- **المكاتب:** التسعة عشر المعتمدة بترتيبها الثابت (`src/delinquency/lib/offices.ts`)؛ أي اسم آخر في القسم لا يُستورد ويُذكر في التنبيهات.
- **الأرقام كما هي:** الأعداد صحيحة فقط، والمبالغ حتى ثلاث خانات عشرية دون تقريب، بأرقام عربية أو لاتينية وفواصل آلاف.
- **لا تخمين:** الخانة المفقودة أو غير المقروءة أو المتعارضة بين عمودين مكررين تُترك **فارغة** وتُعلَّم — لا تصبح صفرًا.
  لا يُحفظ صف إلا إذا اكتملت خاناته العشر؛ المكتب الخالي تمامًا لا يُحفظ ويُذكر ذلك قبل الحفظ.
- **فحوص تلقائية:** اكتمال المكاتب، المكاتب المكررة، مجموع شرائح كل مكتب مقابل إجماليه في التقرير (عمود `1-5555555`)،
  ومجاميع الأعمدة مقابل صف «المجموع الكلي». صف «المجموع الكلي» للمقارنة فقط ولا تؤخذ منه أرقام.
- **الشهر:** يُقترح من سطر «حتى تاريخ» ويمكن تغييره. وجود بيانات محفوظة لنفس الشهر والمكتب يتطلب تأكيد الاستبدال، والحفظ كله في معاملة واحدة.
- **ملفات غير صالحة:** PDF ممسوح ضوئيًا (بلا نص، يحتاج OCR)، محمي بكلمة مرور، أو تالف ← رسالة واضحة ولا يُحفظ شيء.

المبالغ تُحفظ بدقة ثلاث خانات عشرية (كانت خانتين) حتى لا تُقرَّب أرقام التقرير؛ البيانات المحفوظة سابقًا لا تتأثر.

### تقرير Excel

ورقة واحدة «تقرير المتأخرات»، كل صف فرع واحد، والأعمدة بهذا الترتيب:

`الفرع | 1-30 | 31-60 | 61-90 | 91-120 | NPL | مبلغ 1-30 | مبلغ 31-60 | مبلغ 61-90 | مبلغ 91-120 | مبلغ NPL | إجمالي العملاء | إجمالي المبلغ`

الأعمدة الخمسة الأولى أعداد العملاء والخمسة التالية مبالغ المتأخرات. يحتوي التقرير ثلاثة جداول تحت بعضها:
الشهر السابق، الشهر الحالي، ثم الفرق (الحالي − السابق)، ولكل جدول صف «الإجمالي» عند وجود أكثر من فرع.
الإجماليات والفروق صيغ Excel حية؛ الفرع الذي لا بيانات له في أحد الشهرين يظهر «—» ولا يدخل في إجمالي الفرق.
المكاتب المعتمدة تظهر بترتيبها الثابت ثم باقي الفروع أبجديًا. التصدير من جدول مراجعة PDF يعرض المكاتب التسعة عشر
دائمًا بالأرقام المراجَعة كما هي، والمكتب الذي بلا بيانات يظهر «—».

### حفظ البيانات

كل البيانات في IndexedDB داخل المتصفح (قاعدة `risk-delinquency-analysis`) وتبقى بعد تحديث الصفحة وإغلاق المتصفح.
النسخة الاحتياطية JSON تحمل كل بيانات النظام. عند الرفع: السجل الموجود لنفس الشهر والفرع يُستبدل بنسخة الملف،
وما ليس في الملف يبقى كما هو، والعملية كلها تتم في معاملة واحدة (كلها أو لا شيء).

## بنية المستودع

- `index.html` → `src/delinquency/` — النظام الجديد (مستقل: لا يستورد أي ملف من خارج مجلده).
  - `lib/` المحرك الحسابي، مولّد Excel، النسخ الاحتياطي، وقراءة PDF (`pdfText.ts` قراءة النص، `parReport.ts` تحليل التقرير، `pdfImport.ts` نموذج المراجعة)
  - `db/` قاعدة IndexedDB مستقلة باسم `risk-delinquency-analysis`
  - `pages/`, `components/`, `ui/`, `styles/` الواجهة

## التشغيل

```bash
npm ci
npm run dev        # خادم التطوير
npm run typecheck
npm test
npm run build      # ينتج dist/
```

اختبارات قراءة PDF تستخدم تقريرًا اصطناعيًا بأرقام مختلَقة يُولَّد داخل الاختبار (`tests/par-fixture.ts`)؛ لا يُحفظ أي تقرير حقيقي في المستودع.
للتحقق محليًا على تقرير حقيقي: `PAR_SAMPLE_PDF=/path/to/report.pdf npx vitest run tests/delinquency-pdf.test.ts`.

النشر تلقائي إلى GitHub Pages عند الدفع إلى `main` عبر `.github/workflows/deploy.yml`.
