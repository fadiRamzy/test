# نظام إدارة ضباط المخاطر — نسخة مبسطة بإدخال يدوي

> تطبيق ويب عربي (RTL) لقائد فريق مخاطر يشرف على ضباط المخاطر: ملفات الموظفين، دقائق الصرف اليومية، الزيارات الميدانية ودورات مراجعة التقارير، الملاحظات المؤرخة، التقييمات الشهرية والسنوية (8 معايير)، لوحة معلومات يومية، وتقرير موظف عربي قابل للطباعة/الحفظ PDF.

**كل البيانات تُدخل يدويًا وتُخزَّن محليًا في متصفح المستخدم (IndexedDB). لا خادم، لا مزامنة، لا إرسال بيانات، ولا تتبّع.**

- لا يحتاج المستخدم إلى تثبيت أي شيء: الموقع بعد النشر يعمل مباشرة في المتصفح.
- يعمل دون اتصال بعد الزيارة الأولى (عامل خدمة يخزّن **أصول التطبيق فقط**، ولا يخزّن سجلات العمل في الـ Cache).
- يعمل تحت أي مسار فرعي لمستودع GitHub Pages (`https://username.github.io/repo-name/`).

## <a id="النطاق"></a>1) المفهوم والنطاق

النظام أداة متابعة بسيطة، **كل بياناته يدوية بالكامل**: لا جمع آلي للبيانات، ولا استيراد من أنظمة أخرى، ولا تكاملات خارجية، ولا سير عمل معقّد.

النطاق المحدد فقط:

1. الموظفون (ضباط المخاطر) وملف كامل لكل موظف.
2. دقائق الصرف اليومية ومددها ومهلها.
3. الزيارات الميدانية ومراجعة التقارير بدورات متعددة.
4. الملاحظات المؤرخة.
5. التقييم الشهري والسنوي على 8 معايير.
6. لوحة معلومات يومية.
7. تقرير موظف عربي للطباعة/PDF لفترة محددة.
8. إعدادات + نسخ احتياطي JSON واستعادة.

ما تم **استبعاده** بشكل مقصود: الكيانات الفرعية للفروع، بيانات تجريبية، استيراد/تصدير CSV، سجل تدقيق، اعتماد/إلغاء قفل التقييمات، تقويم ساعات العمل، أي تكامل أو API خارجي.

## <a id="الشاشات"></a>2) الشاشات

| الشاشة | المسار | ما تقدمه |
| --- | --- | --- |
| لوحة المعلومات اليومية | `#/` | دقائق واردة اليوم، بانتظار طلب الملف، بانتظار استلام الملف، لم تبدأ المراجعة، بانتظار الرد النهائي، دقائق متأخرة، زيارات جارية، تقارير بانتظار التسليم/المراجعة، مهام متأخرة، وحِمل العمل لكل موظف |
| الموظفون | `#/employees` | إضافة/تعديل/أرشفة/حذف، تصفية بالقطاع والمحافظة والبحث، الرقم التسلسلي وكود الموظف |
| ملف الموظف | `#/employees/:id` | نظرة عامة + تبويبات: دقائق الصرف، الزيارات ودورات المراجعة، الملاحظات (بفلاتر نوع/حالة/تاريخ)، التقييمات |
| دقائق الصرف | `#/minutes` | سلسلة الأوقات: الورود ← طلب الملف ← استلام الملف ← بدء المراجعة ← الرد النهائي، مع المدد وتجاوز المهلة وسبب التأخير والملاحظات |
| الزيارات والتقارير | `#/visits` | أوقات التحرك/الوصول/الإتمام/العودة/تسليم التقرير/مراجعة التقرير/البريد النهائي + **دورات مراجعة متعددة** لكل تقرير |
| سجل الملاحظات | `#/observations` | ملاحظات مؤرخة على الموظف أو دقيقة أو زيارة أو دورة مراجعة، مع فلاتر الموظف/التاريخ/النوع/الحالة |
| التقييمات | `#/evaluations` | تقييم شهري وسنوي على 8 معايير (1–5)، مجموع ومتوسط، تعليقات لكل معيار وتعليق عام، وسجل كامل |
| تقرير الموظف | `#/reports` | تقرير عربي RTL لفترة محددة، يشمل الدقائق والزيارات ودورات المراجعة والملاحظات والتقييمات، مُهيأ لمقاس A4 |
| الإعدادات | `#/settings` | بيانات الجهة وقائد الفريق، مهلة المراجعة، القوائم المرجعية (قطاعات/محافظات/أنواع ملاحظات)، تصدير واستعادة JSON، حذف كل البيانات |

### دقائق الصرف: الحقول المحسوبة

لكل دقيقة تظهر: مدة انتظار الملف (طلب → استلام)، زمن المراجعة (بدء المراجعة → الرد النهائي أو الآن)، الزمن الإجمالي من الورود، وهل تجاوزت المهلة وبمقدار. **كل هذه المدد محسوبة من الطوابع الزمنية المسجلة يدويًا فقط**؛ إذا لم تُسجَّل بعض الأوقات لا يخترع النظام قيمًا بل يعرض «—».

### الزيارات والتقارير: الدورات

يمكن إضافة أي عدد من دورات المراجعة لنفس التقرير. كل دورة تحتفظ بوقتها وملاحظاتها وتصحيحاتها المطلوبة ونتيجتها (بانتظار النتيجة / مقبول / يحتاج تصحيح / مرفوض)، وتُعرض مرتبة زمنيًا، **ولا تُستبدل الدورات السابقة**. يمكن أيضاً إضافة ملاحظة مؤرخة مرتبطة بدورة محددة.

## <a id="الحساب"></a>3) قواعد الحساب

- **مهلة المراجعة**: قيمة واحدة في الإعدادات (افتراضي 60 دقيقة)، تُستخدم لحساب تجاوز المهلة في الدقائق ومراجعة التقارير.
- **زمن المراجعة** يُحسب من «بدء المراجعة» لا من «ورود الدقيقة»، ويظهر زمن انتظار الملف منفصلًا، حتى تُفرَّق فترة انتظار الملف عن فترة العمل الفعلية.
- **التقييم**: 8 معايير، كل معيار من 1 إلى 5.
  - المجموع = مجموع الدرجات **المسجلة** فقط.
  - المتوسط = المجموع ÷ **عدد المعايير المسجلة**.
  - **لا توجد أوزان ولا تصنيفات تقديرية (ممتاز/جيد/…)** يُصدرها النظام — الدرجات والتعليقات تُدخل يدويًا والقرار التقديري يبقى لقائد الفريق.
  - التقييم السنوي لا يمنع الرجوع لمتوسطات الشهور كمرجع مساعد فقط (يظهر بجانب المعيار كمعلومة مدخلة يدويًا).
- **لا تُفرض سياسات شركة**: كل المهل والقوائم المرجعية قابلة للتعديل من الإعدادات.

## <a id="التخزين"></a>4) التخزين المحلي والنسخ الاحتياطي

> **تنبيه مهم:** البيانات مخزَّنة في IndexedDB داخل **هذا المتصفح على هذا الجهاز فقط**.
>
> - لا تتم **مزامنة** البيانات بين الأجهزة أو المتصفحات (لا يوجد حساب ولا خادم).
> - البيانات **تُفقد** إذا حذفت بيانات المتصفح (Clear browsing data / Site data)، أو استخدمت وضع التصفح الخاص، أو غيّرت الجهاز/المتصفح، أو أعدت تثبيت النظام.
> - لذلك صدّر نسخة JSON دوريًا واحفظها خارج المتصفح (قرص/بريد مؤسسي)، قبل أي تحديث كبير أو تغيير جهاز.

**التصدير**: الإعدادات ← «تصدير نسخة JSON» — ملف واحد يحتوي السجلات الخمسة والإعدادات مع عدد السجلات وبصمة تحقق SHA-256.

**الاستعادة**: الإعدادات ← «استيراد نسخة» ← اختر الملف ← يتحقق النظام من البنية والبصمة ويُظهر عدد السجلات، ثم:

- **دمج مع الحالي**: الأحدث يفوز حسب تاريخ التعديل، دون تكرار.
- **استبدال كل البيانات**: يحذف الحالي ويستورد الملف.

في الحالتين يُنزَّل تلقائيًا **ملف أمان** من بياناتك الحالية قبل التنفيذ. أي ملف بتطبيق آخر أو بصمة غير مطابقة أو بنية ناقصة يُرفض مع بيان سبب الرفض.

**لا تُرفع أي نسخة تحتوي بيانات عمل حقيقية إلى المستودع** (`.gitignore` يستثني ملفات النسخ).

## <a id="النشر"></a>6) النشر على GitHub Pages (خطوات دقيقة)

ملف سير العمل جاهز في `.github/workflows/deploy.yml` ويقوم بالآتي عند كل دفع إلى `main`: تثبيت التبعيات → فحص الأنواع → الاختبارات → البناء → رفع `dist` → النشر.

1. أنشئ مستودعًا على GitHub وادفع المشروع:

   ```bash
   cd risk-officer-system
   git init
   git add .
   git commit -m "نظام إدارة ضباط المخاطر"
   git branch -M main
   git remote add origin https://github.com/<USERNAME>/<REPO>.git
   git push -u origin main
   ```

2. في المستودع: **Settings → Pages**.
3. تحت **Build and deployment → Source** اختر **GitHub Actions** (وليس «Deploy from a branch»).
4. اذهب إلى تبويب **Actions** وتأكد من نجاح تشغيل «النشر على GitHub Pages» (job باسم «نشر»).
5. افتح الرابط: `https://<USERNAME>.github.io/<REPO>/` — تعمل أي تسمية للمستودع لأن البناء يستخدم `base: './'`.
6. لا حاجة لأي أسرار (Secrets) أو متغيرات بيئة.

تحديث النسخة بعد ذلك = `git push` فقط؛ سير العمل يعيد البناء والنشر. لا تحتاج إلى ضبط `.nojekyll` يدويًا (يُنسخ تلقائيًا من `public/`).

**تخزين:** قاعدة واحدة `risk-officer-tracker` بإصدار 1، ومخازن: `employees, minutes, visits, observations, evaluations, settings, meta`.

## <a id="اسئلة"></a>9) أسئلة شائعة ومشاكل معروفة

- **هل تظهر بياناتي على جهاز آخر؟** لا. لا مزامنة؛ انقل البيانات بتصدير/استيراد JSON.
- **هل تُرسل بياناتي إلى أي مكان؟** لا. لا يوجد أي طلب شبكة لبيانات العمل، ولا تحليلات، ولا خطوط أو مكتبات من CDN.
- **التطبيق يفتح لكن لا يظهر شيء؟** تأكد من عدم استخدام وضع التصفح الخاص، وأن المتصفح يسمح بالتخزين المحلي، وأنك فتحت الرابط نفسه الذي نشرت عليه.
- **فقدت البيانات بعد تنظيف المتصفح؟** استعد آخر نسخة JSON من الإعدادات.
- **بعد النشر لا يظهر التحديث؟** أعد تحميل الصفحة مرة (عامل الخدمة يجلب الشبكة أولًا عند التنقل) أو امسح بيانات الموقع ثم أعد الفتح.
