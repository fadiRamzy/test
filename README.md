# نظام إدارة المخاطر — إدخال يدوي، شبيه بالإكسل

> تطبيق ويب عربي (RTL) لإدارة ضباط المخاطر: الموظفون، التقييم الشهري والسنوي، الزيارات الميدانية، دقائق الصرف، الملاحظات، الإجازات والأذونات، وتصدير CSV ونسخ احتياطي JSON.
>
> **كل البيانات تُدخل يدويًا وتُخزَّن محليًا داخل متصفح المستخدم (IndexedDB). لا خادم، لا مزامنة، لا إرسال بيانات، ولا تحليلات.**

---

## 1) ما الذي تغيّر في هذه المراجعة (تبسيط وإعادة تصميم)

تم **تعديل المشروع الحالي** (لم يُعَد بناؤه من الصفر) مع الاحتفاظ بما كان يعمل وحذف التعقيد:

| قبل | بعد |
| --- | --- |
| شريط جانبي كبير + 9 صفحات متداخلة | شريط تنقل أفقي واحد بـ 9 أقسام واضحة |
| دقائق صرف بـ 7 طوابع زمنية إلزامية وحالات مركّبة | تاريخ + فرع + عميل + أوقات مختصرة، وأغلبها **اختياري** |
| دورات مراجعة متعددة لكل تقرير (نافذة منفصلة) | حقول مبسطة في سجل الزيارة (تسليم/مراجعة/عدد التعديلات/التقدير) |
| تقييم بـ 8 معايير في نافذة لكل موظف | **جدول تحرير مباشر شبيه بالإكسل**: صف لكل موظف، شارات درجات، إجمالي تلقائي |
| كيان «الفروع» + سجل تدقيق + CSV مستورد + بيانات تجريبية | حُذف كليًا |
| تصنيف تقييم غير موجود في الملف الأصلي | عتبات الملف: <240 ضعيف · 240–<280 مقبول · 280–<330 جيد · 330–<430 جيد جدًا · ≥430 ممتاز |
| لا يوجد سجل إجازات | وحدة **الإجازات والأذونات** (أيام أو ساعات منفصلة) |

## 3) قواعد الحساب (مطابقة لملف الإكسل)

1. **إجمالي التقييم الشهري = عدد الزيارات + مجموع درجات المعايير الثمانية.**
   - لا أوزان، ولا معاملات، ولا توزيع درجات تلقائي.
   - الخلايا الفارغة تُعامل «لم يُقيَّم» ولا تُحسب صفرًا؛ الصف يظهر «ناقص» حتى تُسجَّل المعايير الثمانية.
   - مثال مُتحقَّق منه في الاختبارات: 6 زيارات + (5+4+3+4+5+4+3+5 = 33) = **39**.
2. **المعايير الثمانية** بنفس أسماء الملف: دقة الفحص والمتابعة وإتمام الزيارات الميدانية · دقة التقارير وجودتها وسرعة الاستجابة · متابعة الفروع ودقائق الصرف اليومية · الالتزام بالزيارات والفحص العشوائي ومواعيد الاستجابة · الالتزام بالسياسات والإجراءات والقرارات الإدارية · الحضور والانتظام · التطوير الذاتي وتنمية المهارات · التعاون والعمل الجماعي. كل معيار 1–5 يُدخل يدويًا.
3. **التقييم السنوي**: مجموع الزيارات = مجموع زيارات الشهور المسجلة؛ مجموع النقاط = مجموع إجماليات الشهور المسجلة؛ ثم عتبات الملف تُطبّق على مجموع النقاط.
   - الشهور التي لا تقييم لها **لا تُحسب أصفارًا** — تُعرض كأشهر ناقصة، ويُعلَّم التقدير «مبدئي» إن كانت هناك شهور ناقصة.
4. **دقائق الصرف**: المدة = من وقت الاستلام إلى وقت الرد النهائي (فقط عند تسجيل الوقتين). الدقيقة تُعد «قيد الإجراء» إذا لم يُسجَّل وقت الرد النهائي. لا يُخترع أي وقت ناقص.
5. **الإجازات**: أيام الإجازات تُجمع منفصلة عن ساعات الأذونات؛ الإذن لا يُحوَّل إلى يوم كامل.

## 4) التخزين المحلي والنسخ الاحتياطي

> **مهم:** كل البيانات في IndexedDB داخل **هذا المتصفح على هذا الجهاز فقط**.
> - لا مزامنة بين الأجهزة أو المتصفحات.
> - البيانات **تُفقد** إذا حذفت بيانات المتصفح (Clear browsing data / Site data)، أو استخدمت وضع التصفح الخاص، أو غيّرت الجهاز/المتصفح.
> - احفظ نسخة JSON دوريًا خارج المتصفح (قرص/بريد مؤسسي).

- **التصدير**: «التقارير والنسخ» ← «تصدير نسخة كاملة» (ملف JSON بكل الجداول + الإعدادات + الأعداد).
- **الاستعادة**: «استيراد نسخة» ← يتحقق النظام من التطبيق والبنية ← «دمج» أو «استبدال» ← يُنزَّل **ملف أمان** من بياناتك الحالية تلقائيًا قبل التنفيذ.
- **CSV**: تصدير لكل وحدة (يفتح في Excel العربي بترميز UTF-8).
- ملفات النسخ والبيانات مستثناة من Git عبر `.gitignore` (`*backup*.json`، `backups/`، `exports/`، `data/`).

## 5) التشغيل والنشر

### التشغيل محليًا (للمطوّرين)

```bash
npm ci         # تثبيت التبعيات
npm run dev    # http://localhost:5173
npm test       # الاختبارات
npm run build  # فحص الأنواع + بناء dist/
```

### النشر على GitHub Pages

1. ادفع المشروع إلى مستودع GitHub:

   ```bash
   cd risk-officer-system
   git init && git add . && git commit -m "نظام إدارة المخاطر"
   git branch -M main
   git remote add origin https://github.com/<USER>/<REPO>.git
   git push -u origin main
   ```

2. المستودع ← **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. تبويب **Actions** ← تأكد من نجاح تشغيل «النشر على GitHub Pages» (job «نشر»).
4. افتح `https://<USER>.github.io/<REPO>/` — يعمل مع أي اسم مستودع (`base: './'`)، ولا حاجة لأسرار أو إعداد `.nojekyll` يدويًا.

> ملاحظة: النسخة المنشورة تعمل كتطبيق ويب محلي التخزين (بيانات المتصفح). لا تحتاج إلى تشغيل خادم ولا إلى اتصال بعد أول زيارة.

كما تم التحقق يدويًا في متصفح Chromium حقيقي على نسخة مبنية (Playwright):

- القائمة العلوية = 9 أقسام فقط، وأول صفحة تظهر رسالة واضحة عند عدم وجود موظفين.
- إضافة موظفين، ثم تقييم شهري مباشر في الجدول: 6 زيارات + 33 = **39**، و3 + 32 = **35**، ثم «حفظ الشهر» ورسالة نجاح.
- بعد إعادة تحميل الصفحة: القيم والإجماليات كما هي (استمرارية التخزين).
- التقييم السنوي: يظهر 8 زيارات، 45 نقطة، شهر واحد مقيَّم، والأشهر الناقصة، والتقدير.
- زيارة ميدانية، دقيقة صرف (المدة 80 دقيقة محسوبة تلقائيًا)، ملاحظة بكل الحقول، إجازة 3 أيام + إذن ساعتين، وملف موظف يعرض الخمسة أقسام.
- تصدير نسخة JSON واستيرادها («الملف صالح»)، تصدير CSV (يفتح بعناوين عربية و BOM)، طباعة/PDF للتقييم الشهري والسنوي (صفحة A4 أفقية واحدة).
- إغلاق التبويب وفتحه من جديد: البيانات موجودة.
- بلا أخطاء JavaScript في الكونسول.

## 7) البنية

```
src/
  db/schema.ts      # الكيانات السبعة + المعايير الثمانية + عتبات التقدير
  db/database.ts    # IndexedDB (فتح، CRUD، إعدادات)
  db/repo.ts        # التحقق والحفظ لكل وحدة (+ حفظ دفعة الشهر)
  db/backup.ts      # تصدير/تحقق/استعادة JSON
  lib/calc.ts       # كل الحسابات: الإجمالي الشهري، التقدير السنوي، الزيارات، الدقائق، الإجازات، لوحة المتابعة
  lib/csv.ts        # تصدير CSV بترميز عربي
  state/store.tsx   # تحميل البيانات المحلية + التنبيهات
  state/router.tsx  # موجّه hash
  components/       # Layout (شريط علوي)، ui (أزرار/حقول/جداول/نوافذ)، Icon
  pages/            # Dashboard, Employees, EmployeeProfile, MonthlyEvaluations,
                    # AnnualEvaluations, FieldVisits, Minutes, Observations, Leaves, Reports
  styles/base.css   # الأنماط (RTL، أبيض، أنماط الطباعة A4)
tests/              # 4 ملفات (56 اختبارًا)
public/             # favicon, manifest, 404.html, .nojekyll
```

قاعدة البيانات: `risk-officer-suite` إصدار 1 — مخازن: `employees, monthlyEvaluations, fieldVisits, minutes, observations, leaves, annualNotes, settings, meta`.

> ملاحظة عن قواعد النسخة السابقة: كانت تُستخدم قاعدة `risk-officer-tracker` بهيكل مختلف. لم تُحذف بياناتها، لكن الواجهة الحالية تقرأ من القاعدة الجديدة `risk-officer-suite`. إن كان لديك بيانات قديمة مهمة، صدّرها من نسخة التطبيق السابقة كملف JSON قبل إزالتها.

## 8) ملاحظات ومحدوديات

- لم يُرفَق ملف الإكسل الأصلي مع الطلب؛ بُنيت القواعد على المواصفات المكتوبة التي وردت في الطلب: أعمدة الشهر، المعايير الثمانية، معادلة الإجمالي (زيارات + درجات)، وعتبات التقدير الخمس. إن اختلف شيء في الملف الأصلي (مثل وجود أعمدة إضافية أو معادلة مختلفة لعمود الإجمالي)، أرسل الملف وسأطابق الحسابات عليه بالكامل.
- لا تُوجد تقييمات آلية ولا خصم تلقائي بسبب الملاحظات أو الغياب — كل الدرجات يدوية كما في الملف.
